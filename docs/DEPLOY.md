# 部署教學

標示 ⚠️ 的步驟需要你在微信平台或開發者工具手動操作，程式碼無法代勞。
整個流程走完大約 30–60 分鐘（不含審核等待）。

---

## 0. 前置需求

- Node.js 18 或 20（Taro 4 與雲函數執行環境都支援）
- 微信開發者工具（最新穩定版）
- 一個微信號

## 1. ⚠️ 註冊小程序帳號、取得 AppID

1. 到 <https://mp.weixin.qq.com> → 立即註冊 → **小程序**。
2. 個人或企業主體皆可使用雲開發。個人主體可選的服務類目較少（例如「工具」「生活服務」等），遊戲玩法屬於一般小程序而非「小遊戲」，不需要遊戲類目。
3. 完成郵箱驗證與資訊登記後，進入後台 → **開發 → 開發管理 → 開發設置**，複製 **AppID（小程序ID）**。
4. 把 AppID 填進專案根目錄 `project.config.json` 的 `"appid"` 欄位。

## 2. 安裝依賴並建置

```bash
cd guess-party
npm run setup        # = npm install + 雲函數 npm install + 雲函數 tsc 建置
npm run cloud:test   # 應看到 46 個測試全部通過
npm run build:weapp  # 產生 dist/（開發時可改用 npm run dev:weapp 自動重新編譯）
```

## 3. ⚠️ 微信開發者工具匯入專案

1. 開啟開發者工具 → 匯入專案。
2. **目錄選專案根目錄 `guess-party/`**（不是 `dist/`）。`project.config.json` 已設定 `miniprogramRoot: "dist/"` 與 `cloudfunctionRoot: "cloudfunctions/"`，工具會自動找到兩者。
3. AppID 選剛才的小程序；後端服務選「微信雲開發」。
4. 右上角「詳情 → 本地設置」確認：
   - 調試基礎庫 ≥ **2.21.2**（`watch` 需 2.8.1+、暱稱輸入框需 2.21.2+；專案預設 3.4.0）
   - 不勾選「ES6 轉 ES5」「上傳時樣式自動補全」「代碼壓縮」（Taro 已處理）

## 4. ⚠️ 建立雲開發環境

1. 工具列點 **「雲開發」** → 開通（首次需同意協議）。
2. 建立環境，名稱自取，例如 `guess-party`。基礎版免費額度足夠開發與小規模使用。
3. 在雲開發控制台 → **設置 → 環境設置** 複製 **環境 ID**（格式像 `guess-party-1g2h3j4k5l6m`）。
4. 填入 `src/config.ts`：

   ```ts
   export const CLOUD_ENV = 'guess-party-1g2h3j4k5l6m'
   ```

   然後重新 `npm run build:weapp`。

## 5. ⚠️ 建立資料庫集合與權限

雲開發控制台 → **資料庫**，建立以下 5 個集合（名稱需完全一致）：

| 集合 | 權限設置 → 自定義安全規則 |
| --- | --- |
| `rooms` | `{ "read": true, "write": false }` |
| `players` | `{ "read": true, "write": false }` |
| `rounds` | `{ "read": false, "write": false }` |
| `votes` | `{ "read": false, "write": false }` |
| `guesses` | `{ "read": false, "write": false }` |

操作方式：點集合 → 右側「權限設置」→ 選「自定義安全規則」→ 貼上 JSON → 確定。
`docs/db-rules/` 內有這些 JSON 檔可直接複製。

> 為什麼：`rooms`/`players` 需要前端 `watch` 才能即時更新，所以可讀；寫入一律不開放（雲函數不受此限制）。`votes`/`guesses` 完全不可讀是「前端拿不到完整投票資料」的保證。

接著建立索引（集合 → 索引管理 → 新增）：

| 集合 | 索引欄位 | 唯一 |
| --- | --- | --- |
| rooms | `code` 升序 | 否 |
| players | `roomId` 升序 | 否 |
| votes | `roundId` 升序 + `pid` 升序 | 否 |
| guesses | `roundId` 升序 + `pid` 升序 + `acked` 升序 | 否 |

資料量小的時候沒有索引也能跑，但正式使用請建立。

## 6. ⚠️ 部署雲函數

1. 確認已執行過 `npm run cloud:build`（`cloudfunctions/game/dist/` 存在）。
2. 在開發者工具左側檔案樹找到 `cloudfunctions/game`，**右鍵 → 上傳並部署：雲端安裝依賴（不上傳 node_modules）**。
3. 等待部署完成（約 1 分鐘）。
4. 雲開發控制台 → **雲函數 → game → 配置**：
   - 超時時間：建議 10 秒（預設 3 秒偶爾不夠）
   - 環境變數：新增 `PID_SALT` = 一串隨機字串（例如 32 字元），用來加鹽產生玩家公開 ID。**設定後不要再改**，否則進行中的房間身份會對不上。
5. 右鍵 `cloudfunctions/game` → **雲端安裝依賴** 若失敗，可改用「上傳並部署：所有文件」（會上傳本機 node_modules，較慢）。

> 每次修改 `cloudfunctions/game/src/*.ts` 後都要：`npm run cloud:build` → 重新上傳部署。

## 7. 本地測試與多人測試

### 單人冒煙測試

1. 開發者工具 → 編譯。首頁應正常顯示；輸入暱稱 → 「開一個新房間」→ 應進入大廳並看到 6 位房間碼。
2. 若出現「伺服器回應異常，請確認雲函數已部署」：檢查步驟 6；若出現 `-501000`/權限錯誤：檢查步驟 5。
3. 雲開發控制台 → 資料庫 → `rooms` 應出現一筆資料。

### 多人測試（開發者工具）

開發者工具提供多帳號模擬：**工具 → 多賬號調試**，可開啟多個以不同測試 openid 登入的視窗。
每個視窗都是一位獨立玩家：

1. 視窗 A 建房 → 視窗 B、C 用房間碼加入 → B、C 按「我準備好了」→ A 按「開始遊戲」。
2. A 出題 → 三個視窗分別投票 → 三個視窗分別猜測 → 各自看到結果 → 各自按「看完了」→ 進入第 2 回合，應由 B 出題。
3. 關閉視窗 B 再重新開啟 → 首頁應顯示「回到房間」→ 點擊後回到正確階段。

### 多人測試（真機）

1. 開發者工具 → **預覽** → 用你的微信掃 QR code。
2. 其他測試者需先加為 **體驗成員**（見步驟 8）或 **開發者**（後台 → 成員管理）才能掃同一個預覽碼。
3. 真機才能驗證：微信分享邀請、暱稱快速填入、切到背景再回來的重連。

## 8. ⚠️ 上傳體驗版

1. 開發者工具右上角 **上傳**，填版本號（例如 `0.1.0`）與備註。
2. 後台 → **管理 → 版本管理** → 開發版本 → 「選為體驗版」。
3. 後台 → **管理 → 成員管理 → 體驗成員** 加入朋友的微信號（上限視主體類型而定）。
4. 體驗成員掃體驗版 QR code 即可遊玩；不需要審核。這是最適合「找 3–12 個朋友實測」的階段。

## 9. ⚠️ 提交審核與發布

1. **服務類目**：後台 → 設置 → 基本設置 → 服務類目，選一個符合主體可用的類目（個人主體常見為「工具 → 效率」或「生活服務」）。
2. **用戶隱私保護指引**：後台 → 設置 → 基本設置 → 用戶隱私保護指引。本專案使用了「微信暱稱」快速填入（`<Input type="nickname">`），需要在指引中勾選「微信暱稱」。若不想處理隱私指引，把 `src/pages/index/index.tsx` 中的 `type="nickname"` 改為 `type="text"` 即可。
3. 後台 → 版本管理 → 開發版本 → **提交審核**，填寫功能說明（例：「多人派對問答遊戲，玩家建立房間後輪流出題、匿名投票並猜測他人答案」）、測試帳號不需要。
4. 審核通常 1–7 天。通過後在版本管理按 **發布**。
5. 發布後若雲函數有更新，直接重新部署雲函數即可，不需重新審核；小程序前端有變更才需要再次上傳審核。

## 10. 日常開發流程

```bash
npm run dev:weapp          # 前端自動編譯，開發者工具會即時刷新
npm run cloud:test         # 改雲函數邏輯後先跑測試
npm run cloud:build        # 再建置 → 開發者工具右鍵上傳部署
npm run typecheck          # 前端型別檢查
```

## 疑難排解

| 現象 | 可能原因 |
| --- | --- |
| `Cloud API isn't enabled` | 基礎庫過舊，或 `src/config.ts` 環境 ID 未填 |
| 建房後畫面卡在「正在進入房間…」 | `rooms`/`players` 權限未設為可讀，`watch` 被拒 |
| 投票按下沒反應、Console 出現 `-502001` 以外的資料庫錯誤 | 集合未建立或名稱拼錯 |
| 第二位玩家加入後第一位沒看到 | watch 未成功，檢查控制台 → 雲開發 → 資料庫 → 實時推送連線數是否超額 |
| 分享卡片無法開啟 | 分享只在真機有效；開發者工具不支援 |
| `callFunction` 超時 | 雲函數超時時間調到 10 秒；首次冷啟動較慢屬正常 |
